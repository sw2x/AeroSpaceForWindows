[#installation]
== Installation

Extract `AeroSpace-Windows-x64.zip` and keep all executables, DLLs, manifests and resource directories together. Start `AeroSpaceApp.exe`; its notification area menu provides Enable/Disable, Reload Configuration and Quit. Use `aerospace.exe` from PowerShell to control the running application. The application and client have distinct filenames because Windows filenames are case insensitive.

[source,powershell]
----
Start-Process .\AeroSpaceApp.exe
.\aerospace.exe list-windows --all
----

[#emulation-of-virtual-workspaces]
== Workspaces

AeroSpace maintains independent workspaces. Each monitor displays one workspace, and changing workspaces hides the previous workspace's windows and shows the next one's windows. Windows virtual desktops are not controlled by AeroSpace. Eligible windows on the current Windows virtual desktop are managed.

`aerospace enable off` restores hidden windows and releases hotkeys. Quit also restores hidden windows. A recovery watchdog and a per-session journal restore windows after an unexpected application exit.

[#config]
== Configuration

AeroSpace chooses an explicit `--config-path` first, then `HOME/.aerospace.toml` (falling back to `USERPROFILE`), then `%APPDATA%\AeroSpace\aerospace.toml`, then its bundled default configuration. An explicit unreadable or invalid path is an error.

[#default-config]
=== Default configuration

Start from xref:config-examples/default-config.toml[default-config.toml]. The default provides workspaces 1 through 5, eight-pixel gaps and Alt-based shortcuts. Set `auto-reload-config = true` for automatic watching; `aerospace reload-config` reloads explicitly. Failed reloads preserve the last accepted configuration and bindings.

[#binding-modes]
=== Binding modes

Bindings are grouped under `[mode.<name>.binding]`. The main mode is active at startup; `mode <name>` changes the active set. Modifiers are `alt`, `ctrl`, `shift` and `win`. Shortcuts reserved by Windows or another application may fail to register. A failed registration preserves the previous set.

[source,toml]
----
[mode.main.binding]
alt-h = 'focus left'
alt-shift-h = 'move left'
alt-1 = 'workspace 1'
alt-shift-1 = 'move-node-to-workspace 1'
alt-enter = 'exec-and-forget Start-Process notepad.exe'
----

[#exec-and-forget]
=== Launching applications

`exec-and-forget` runs the remainder of the configuration string as a PowerShell script. It starts a detached process and does not capture its output or wait for it. Use PowerShell quoting within the TOML string. See xref:aerospace-exec-and-forget.adoc[exec-and-forget].

[#on-window-detected-callback]
=== Window detection rules

Rules under `[[on-window-detected]]` can match executable IDs and window titles, then run layout or workspace commands. The application ID is the executable filename in lowercase, such as `notepad.exe`.

[source,toml]
----
[[on-window-detected]]
if.app-id = 'notepad.exe'
run = 'layout floating'
----

[#tree]
== Layout tree

Workspaces contain nested layout containers and windows. `tiles` distributes container space; `accordion` gives the focused window more space and keeps adjacent window strips visible. Containers have horizontal or vertical orientation. `join-with`, `split`, `move`, `resize`, `balance-sizes` and `flatten-workspace-tree` edit this tree.

`layout floating tiling` toggles a window between a floating position and the tree. Dialogs and fixed-size windows begin floating. `fullscreen` uses AeroSpace's workspace layout; it does not request an application's native fullscreen mode.

[#normalization]
=== Normalization

The two normalization options flatten redundant containers and alternate orientations in nested containers. They are enabled by default. Disable them in configurations that use explicit `split` operations to retain the requested nesting.

[#multiple-monitors]
== Monitors

`list-monitors` reports monitor IDs and names. Workspaces can move between monitors with `move-workspace-to-monitor`; `move-node-to-monitor` moves a window and `focus-monitor` changes focus. Taskbar areas are excluded from normal layouts. Monitor positions use Windows desktop coordinates, which may include negative origins.

[#assign-workspaces-to-monitors]
=== Workspace assignment

`workspace-to-monitor-force-assignment` maps workspace names to monitor patterns. Use monitor names or the documented monitor selectors to keep a workspace on a chosen display.

When adding or removing displays, AeroSpace refreshes monitor information and arranges visible workspaces again. Application minimum sizes and Windows foreground rules can prevent exact geometry or focus requests.

[#shell]
== Commands and scripting

Run `aerospace --help` or `aerospace <command> --help`. xref:commands.adoc[Command references] describe the retained commands. `eval` supports multiple AeroSpace commands and command combinators. `--window-id` values are AeroSpace model IDs, not raw HWNDs.

Listing commands support structured output with `--json` and format fields such as `%{app-id}`, `%{app-pid}`, `%{app-exec-path}` and `%{app-executable-directory}`. Query commands address the running application through a user/session-scoped named pipe.

[#environment-variables]
=== Environment variables

Commands invoked through the CLI can use `AEROSPACE_WINDOW_ID` and `AEROSPACE_WORKSPACE` to address a window or workspace. IDs identify AeroSpace model windows and can become invalid when the corresponding window closes.

== Unsupported features

The macOS commands `macos-native-fullscreen`, `macos-native-minimize`, `volume` and `debug-windows` are removed. `move-mouse` and `subscribe` are also unavailable. Configuration keys `start-at-login`, `automatically-unhide-macos-hidden-apps` and `focus-follows-mouse` are rejected. Configure automatic startup through Windows if desired.
